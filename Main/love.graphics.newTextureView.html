love.graphics.newTextureView

From LOVE
Available since LÖVE 12.0
This function is not supported in earlier versions.

Creates a new Texture that shares its pixel memory with an existing texture, but can use a different pixel format, texture type, or a subset of its mipmap levels and layers.

Rendering to or writing to one of them is visible in the other: no pixels are copied.

Function

Synopsis

view = love.graphics.newTextureView( base, settings )

Arguments

Texture base
The texture to create a view of.
table settings
A table with the following optional fields:
PixelFormat format (base format)
The pixel format of the view. It must be the base texture's format or one of the formats listed in its viewformats setting (see Texture:getViewFormats).
TextureType type (base type)
The texture type of the view, for example a single layer of an array texture viewed as a "2d" texture.
number mipmapstart (1)
The first mipmap level of the base texture visible in the view.
number mipmapcount (all)
The number of mipmap levels in the view.
number layerstart (1)
The first layer (slice) of the base texture visible in the view.
number layers (all)
The number of layers in the view.
string debugname (nil)
A name shown by graphics debugging tools.

Returns

Texture view
The new texture view.

Notes

Typical uses: treating an srgba8 texture as rgba8 (or the other way around), rendering into one layer of an array texture or one face of a cubemap, or sampling a single mipmap level.

Examples

Render into one layer of an array texture

local layers = love.graphics.newArrayTexture(256, 256, 4, {canvas = true})
local layer2 = love.graphics.newTextureView(layers, {type = "2d", layerstart = 2, layers = 1})

love.graphics.setCanvas(layer2)
love.graphics.clear(1, 0, 0, 1)
love.graphics.setCanvas()
